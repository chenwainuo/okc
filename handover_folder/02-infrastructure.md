# 02 — Infrastructure

## The judge (okc)
- `okc` CLI is installed locally; the loop wraps it: `python3 -m proj_rsi {status,lint,cpu-check,result,board,check,wait,propose,review,decide,incumbent,quota}` (code in `proj_rsi/__main__.py`, `runner.py`, `ledger.py`, `score.py`, `okc_result.py`, `static_check.py`, `correctness.py`).
- A check: `python3 -m proj_rsi check proj_rsi/candidates/<cand> --experiment <cand> --against <job>` (lint → quota guard → `okc check` with --no-wait → wait → archive to `results/proj-rsi/jobs/<job>.{json,log,txt}` → ledger). Add `--scored` for a scored submission (counts on the board). `--reserve N` keeps N checks back.
- Quota: 20 checks + 10 scored per day, reset 00:00 UTC, unused slots expire. At handover (19:05 UTC): checks 0 left, scored 4 left (6 used: pw33, pw34 ×2, pw35, …). Runs take ~10 min; prepare ≤ 300 s (we budget 240 s).
- Judge = H200 (132 SMs, 50 MB L2, HBM 4.8 TB/s peak, ~3.6–3.8 achievable). It regenerates weights every run, cold-flushes L2 before each replay, captures kernel_fn in a CUDA graph, paired timing vs SGLang, ~4 µs launch floor. It profiles every shape with CUPTI (per-kernel table in the `.txt` report) — the single most useful diagnostic we have of the real machine.
- Reports: `results/proj-rsi/jobs/<job>.txt` (score, per-shape table, CUPTI profiles), `.log` (prepare stdout: our BAKE/PICK/PROBE lines), `<cand>.scored.txt` / `<cand>.report.txt` (summaries written by the detached waiters).
- Ledger: `results/proj-rsi/ledger.json` (incumbent = pw34 846e25d9df09433f; experiments pw1…pw35, rs128…).

## The H100 box (the iteration instrument)
- `root@107.170.6.60` (DigitalOcean H100 SXM 80 GB, default ssh key `~/.ssh/id_rsa`; `ssh -o BatchMode=yes` works). Ubuntu 26.04, nvidia-driver-580-server, docker + nvidia-container-toolkit. Earlier box 162.243.109.198 never accepted keys — ignore it.
- Repo mirror `/root/okc` (rsync from `/home/ubuntu/okc`: `rsync -az -e "ssh -o BatchMode=yes" --exclude __pycache__ proj_rsi muse_bf16_proj root@107.170.6.60:/root/okc/`); agents rsync their own candidate dirs before each run.
- Container runner `/root/okc_run.sh <cmd>`: `docker run --rm --gpus all --ipc=host -v /root/okc:/okc -v /root/okc_cache:/root/.cache -w /okc -e TORCH_EXTENSIONS_DIR=/root/.cache/torch_extensions -e TORCH_CUDA_ARCH_LIST=9.0a pytorch/pytorch:2.8.0-cuda12.8-cudnn9-devel`. The ARCH_LIST is essential: torch 2.8 otherwise appends compute_90/sm_90 gencode flags that break hand-written wgmma extensions (the judge's torch does not add flags; candidates pass `-gencode arch=compute_90a,code=sm_90a` themselves and guard wgmma/setmaxnreg with `__CUDA_ARCH_FEAT_SM90_ALL`).
- GPU lock `/root/gpu_lock.sh <cmd>` = `flock -w 7200 /tmp/gpu.lock`. EVERY timing run must hold it; at handover the queue was 13 deep (≈8 agents). Agents should batch variants into one locked run and compile outside the lock with `h100_bench.py … --prepare-only`.
- `/root/bench.sh <tag> <path-under-/okc> [args]` runs the harness under the lock, log `/root/okc/logs/<tag>.log` (ends with `BENCH_DONE`) + `.json`. Logs per track: `/root/okc/logs/{rs128,rs32,rs128p,latency,bandwidth,contrarian,tensorcore,pw29m,pw35ref}*`.
- `/root/soak_stop.sh` kills the soak container (`proj_rsi/tools/soak.py`). The soak polluted all measurements (12.6 µs empty-graph replay, bakes +3–4 µs) — it is stopped and must stay stopped while agents measure. "Keep the GPU busy" is now satisfied by the agents' lock queue.
- Box vs judge: replay overhead ~9 µs on the box vs ~4 on the judge; H100 HBM 3.35 TB/s peak (2.8 achievable) vs H200 4.8; big-shape kernel times scale ~0.7× to the judge; fixed per-CTA latencies do NOT shrink (transfer rule, see 03). In-prepare bake numbers are ~4–7 µs above judge-measured numbers (no graph). Compare only within one run and one position (run order shifts small shapes by ±1 µs: P3 saw +1.33/−1.23 on decode1 router depending on which prepare ran first).

## Local harness and tools (`proj_rsi/tools/`)
- `h100_bench.py <submission> [--official] [--shapes …] [--layers …] [--reps 20] [--json out] [--prepare-only] [--no-torch-baseline]`: reference weights (muse_bf16_proj/reference.py), prepare (prints the candidate's BAKE/PICK lines), `check_implementation` on judge-like cases (+ official m = 5,7,9,33,130,512,1000 with --official), then judge-style timing (graph replay after an L2 READ flush — a write flush leaves L2 dirty and changes m=256 rankings), torch baseline, H100 SOL. Prints `REPLAY_OVERHEAD` and `READ6MB` probes first.
- `soak.py` (do not run), `codec_e.py`/`codec_e_emu.py`/`plane_pack.py` (codec studies, closed), `cstrip.py` (comment stripper preserving line numbers, used to shrink pw25 under 1,000,000 bytes), `cutlass_sweep.py`, `*_emu.py` (CPU emulators of kernels' index math).
- Clean-room school tools: `proj_rsi/cleanroom/latency/{prof.py (CUPTI kernel-only timing), mb_load.py (loader microbenchmark), stamps.py, lab.py}`, `contrarian/{sweep.py,test_red.py,check_all.py}`, `tensorcore/tools/*`.
- `proj_rsi/static_check.py` (lint): forbids host syncs, network/subprocess, flags wgmma/setmaxnreg/multicast builds without compute_90a, enforces the 1,000,000-byte upload limit (error > 1e6, warning > 950 k). The "several load_inline builds: confirm sm_90a" warning is expected for pw3x/rs*.
- `proj_rsi/okc_result.py` parses PROBE lines (regex widened several times; accepts trailing key=value tokens).
- Detached helpers (session scratchpad `/tmp/claude-1000/-home-ubuntu-okc/8dda88b9-22f0-4310-b863-aa591883e787/scratchpad/`): `launch_detached.sh <script>` (setsid nohup) and `submit_pw34c.sh`, `submit_pw35.sh`, `wait_*.sh` patterns. The scratchpad dies with the session — recreate under a new session's scratchpad or under `results/proj-rsi/`. Background shells started with the Bash tool were killed twice by `kill`/exit-144 — use the detached helper for anything that must outlive a turn.
- The LOOP head log: `proj_rsi/LOOP.md` (980 lines; section per iteration; the "Drawing board v2" and "18:30 UTC — where the remaining score-µs are" sections hold the ceiling analysis). Audits in `proj_rsi/audits/` (titles listed in 10-closed-tracks.md).
