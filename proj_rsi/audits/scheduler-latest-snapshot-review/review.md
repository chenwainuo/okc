The current-state argument is sound under the existing cooperating-writer contract. `_commit` writes a checksummed complete snapshot, not a delta requiring older events. The stable lock inode and exclusive flock remain held across read, state change and append/fsync. Each operation reads the actual final complete record bytes, checks the checksum and snapshot envelope, and compares its sequence with the instance's floor. It does not authorize work from a checkpoint, persisted cache or metadata memo. Claim/resource/ownership/dependency/source-review checks are unchanged and still run under that lock. A concurrent normal strict CLI writer and the opted-in worker use the same lock and WAL format; the worker sees the new complete snapshot on its next operation.

The accepted change concerns historical fault-detection timing. Strict constructor startup audits the existing history once before enabling latest reads. Explicit `audit()` retains strict history verification. Older checksum/sequence-chain corruption that leaves the latest complete snapshot valid is deferred to those audits. That does not alter current state reconstructed from the latest full snapshot. Requiring another all-history scan on every poll would remove the proposed optimization without improving current-state reconstruction. The help text discloses this tradeoff, and normal CLI commands/default work remain strict.

Torn-final handling remains the existing recovery: save the incomplete tail as evidence, truncate it durably to the last newline, then validate the surviving complete record. A running instance refuses a surviving sequence below its observed/committed floor, including empty or missing WAL after state was seen. Latest-record corruption is rejected immediately. A reverse scan spanning multiple64KiB blocks is tested. Common noncooperating file changes during a read are rejected by inode/size/time comparisons after reading and checking the actual bytes.

The floor is a local observation bound, not a durable global antirollback anchor. It cannot detect rollback below an unseen external commit while remaining at/above its own floor, or a valid old prefix presented to a fresh process. Original strict replay also accepts such a valid prefix; scanning all remaining history does not reveal a deleted valid suffix. Same-sequence valid self-checksummed rewrites and arbitrary writers bypassing the stable lock are outside the existing accidental-corruption/cooperating-writer guarantee. This GO does not add a malicious-owner or arbitrary concurrent in-place-write guarantee.

CLI wiring is suitably narrow. Only the work subcommand accepts the flag. Its store constructor performs the strict startup before dispatcher construction, so corrupt history refuses execution before any dispatcher is reached. The same store object then lives through the bounded worker loop. `run-next`, registration, status and unflagged work keep the default strict mode. No worker-loop, remote launch, cleanup or promotion policy changes are in this patch. Root's proposed natural-drain boundary followed by one new-worker strict startup fits this opt-in design; this reviewer did not perform it.
