# P1 on the H100 box: small-shape router / unpooler / o (2026-10-26, pw27h)

All times are **in-prepare µs** (`_time_us` / `_tm`: a cold-L2 read pass queued ahead, events around one graph
replay, median; empty graph ≈ 3.2–3.6 µs on this box) unless marked "kernel-side" (gv bake, empty graph subtracted).
The harness's table (`yours_us`) is **not usable for these shapes**: its replay is launched from an idle GPU, so it
mostly times the CPU graph launch (REPLAY_OVERHEAD 11–13.5 µs vs router m=1 totals 11.8–13.4, ±1.5 run to run).
Every "vs r6" delta below is an alternated measurement in the same run (`PROBE p1alt`, 3 × 21 replays each, min).

## 1. Read floor (pw27 PROBE rd8, 8 MB)
ld.global 16 B, everything issued at launch: 128 CTAs 7.20, 132 7.26, 264 6.66, 528 6.75, 1056 6.69;
cp.async.bulk 8/16 KB at 128 CTAs 6.82/6.78, 8 KB at 256 6.88. So the floor is ≈ 6.7 (≈ 3.3 µs kernel-side,
≈ 2.5 TB/s) at ≥ 2 CTAs/SM; 1 CTA/SM costs +0.5; bulk = ldg. Few-CTA streaming is dead: 32 CTAs with a 192 KB
bulk ring read 8 MB in 10.37 (p1/probe.py --bulk).

## 3. Implementation (pw27h, gv kernel)
V bit 27 (`z`): thread 0 takes a per-tile ticket (atomicAdd, result used only at the end); warp 0 of the tile's
split-0 CTA zeroes the tile, fences, bumps the tile flag, then issues its loads; before the reduction thread 0
spins on `ld.acquire.gpu` until flag ≥ ticket/S + 1, bar.sync, red.add (fp32 router; packed bf16x2 unpooler).
No memset node, no cluster, one kernel. Split-0 CTAs are z = 0, dispatched first: no co-residency requirement.
Counters: one 2048-int tensor per gv instance (`st["p1cnt"]`), monotone (epoch = ticket / S).
V bit 29 (`x`): same flag protocol, the zeroing done by an extra z-plane of zeroer CTAs. V bit 28 (`p`): PDL zero
kernel. rr<1,1,1024> (`rr6`): r6's fp32 m=1 router at 1024 threads.

## 6. What transfers to the H200 judge
The removed cost is latency (cluster barriers / a second graph node vs one L2 round trip each side), not bandwidth,
so it should transfer nearly 1:1, while the stream part shrinks ×0.7. On the judge r6's router grows 4.35 → 4.88 /
5.28 / 6.29 from m=1 to 8/16/32 (+0.53/+0.93/+1.94); on the H100 our paths sit +0.3/+0.45/+0.65 over rr0, so expect
≈ 4.6 / 4.8 / 5.0 judge-µs (−0.3/−0.5/−1.3) and the m=1 rr6 −0.2. The unpooler gain (−0.2…−0.5 here) is within
run-to-run noise of the judge's 4.4–4.6 and carries a 100× larger (still passing) error; ship it only if the
judge's bake confirms. Expected ≈ 2.3 judge-µs over the four router shapes + ≤ 0.5 unpooler.
Ship: router buckets 8/16/32 with rk-s8z, rk-s16w8z, rk-s16w8x, rk-s32x baked against r6 (the bake picks),
RRB {1: (0, 6, 7)}; unpooler uk-s4z, uk-s4x, uk-s4w4x baked against r6. PR27 off; the pw23 m=128/256 router
bake unchanged. pw27h prepare on the box: 42–45 s.
