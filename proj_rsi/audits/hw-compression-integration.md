## Failure and ownership contract

Unsupported feature, declined allocation attributes, optional compile failure or a recoverable allocation failure may disable the new path only while CUDA remains healthy and cleanup is successful. Preserve the original selected p. Do not catch every RuntimeError and call the ordinary kernel: illegal address/assert/launch failure/lost or destroyed context, failed synchronization, unmap/release failure, poisoned output or unknown CUDA health must propagate and invalidate preparation. The lab's warning-only constructor destructor is insufficient as a production error channel: an authorized port must surface constructor cleanup status and reject retained-resource warnings. No silent fallback after a fatal asynchronous fault.

Prepared state must retain the foreign Region owner, from_blob tensor and any ordinary fallback data for the entire lifetime of every graph user. A captured raw address is not a Tensor/Region reference. No optional repick, state pruning or late unmap may invalidate a captured graph. Require the runner/callable to retain prepared state until all graph execs are destroyed; if that lifetime cannot be established, defer release until CUDA context teardown rather than eagerly freeing by Tensor GC. Integration needs an explicit reviewed ownership contract, not just a from_blob deleter.

Prepare copy uses the actual current Torch stream/context/device, completes before capture, and retains immutable packed bits thereafter. Explicit teardown order: finish submitted work; destroy every graph exec referring to the allocation; release captured output/state/tensor aliases; then checked original-context synchronize→unmap→release handle→free reservation. Never cudaFree foreign memory or remap a live address. All these operations stay outside kernel_fn.
