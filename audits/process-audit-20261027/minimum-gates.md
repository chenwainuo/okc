# Minimum gates for faster experiments

**Agree with the simplified process.** Run a cheap bounded smoke and same-run timing on actual affected shapes first. Move a useful candidate to the complete current-policy comparison and official check promptly. Exact unrelated SASS equality, all-K basis on every arm, repeated unchanged proofs, mandatory profiling and successive review stages should not be universal launch requirements. Learning/history work proceeds alongside the next experiment. This is advice for the next protocol revision; no frozen receipt is changed.

Keep these concrete safeguards within the existing smoke, without adding another approval stage:

- **Bound execution and preserve failures.** Retain the existing timeout, exclusive GPU owner, launch/status checks, failure output and drain/process cleanup. A source bug, failed async build or fallback must not silently turn the measurement into another kernel. Save raw resource/query/error fields before assertions. PW44 and MoE v2 show why binary SHARED and runtime user-static bytes must remain different fields; their reporting mismatch was a harness failure, not a numerical failure.
- **Exercise the actual integration boundary once.** Use the real generated module subset and completed prepared state, and record selected symbol, shape, source/build identity and hardware. PW41's small module correctly lacked large-module functions; GV revision2 requested a cache that prepare had deleted. A real smoke addresses these issues more directly than more copied-constant mocks. A fixed diagnostic is allowed even when unselected; label it separately. Preserve original prepare clocks/selectors for claims about the actual policy.
- **Make the small oracle discriminate the changed behavior.** Check an independent expected value on fresh normal/outlier/zero input plus a few relevant boundary/index cases, actual current input, poisoned output and the timed terminal result before another replay or repair. Include touched counters, aliases/immutable storage and relevant empty→valid/valid→empty transitions. Do not blindly poison storage whose contract requires persistent zeros. MoE v1's subnormal-scale counterexample shows that random normal inputs alone can miss a changed numeric representation; exercise its problematic scale/rounding domain when that representation changes. Unchanged codec/layout receipts can be reused.
- **Review new hazards before launch, proportionately.** Changed addresses, ownership, barriers, async lifetimes or cooperative residency need a focused source/race/deadlock argument and a boundary fixture. A smoke cannot prove a latent cross-CTA race absent. This does not require whole-kernel unrelated SASS equality, an exhaustive instruction interpreter or universal sanitizer runs. Escalate machine-code inspection only where compiler output is material to the changed hazard or claimed mechanism.
- **Time the complete measured path fairly.** Keep required zeroing/reduction work inside the measured graph, cold-cache treatment where the task requires it, same fixtures, simple balanced order and finite raw samples. Preserve every tiny signed result and conflicting F1/paired estimate. RQ predxor's positive actual-policy aggregate coexists with a fixed pooler ST5 paired loss and an O32 selection regression; none warrants hiding the others or a new significance hurdle.

“Promising” means there is a useful measured positive or a specific unresolved comparison worth answering; it must not become a new effect-size or significance threshold. Complete actual-policy coverage is needed before claiming a cumulative package gain, because shared templates and fresh selection can affect QKV/O or other loads. It is not required before every bounded mechanism screen. A prior valid fullpolicy point should proceed to the already-authorized official check/submission path without waiting for history prose or another causality review.

Freeze executable/runtime inputs and the necessary build recipe. Hash collected logs as evidence at collection, rather than making mutable test logs launch dependencies: the RQ independent reproducer changed only unittest's elapsed-time line and otherwise broke a valid descriptor pin. Retain evidence and prior failures; do not require shipping/revalidating the entire historical archive on every launch. Reuse the corrected launcher/query/timing helpers and real failure fixtures; no new framework is needed.
